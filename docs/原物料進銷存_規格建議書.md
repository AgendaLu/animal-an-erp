## 1. 關鍵決策（最終版）

| 議題 | 決議 |
|---|---|
| 庫存模型 | **原裝品（Bulk）／分裝品（Sellable SKU）分離，共用統一庫存帳本**（`item_kind` 區分） |
| 成本計價 | **批次成本**：每批進項各自記成本；出庫與毛利依該批成本計算 |
| 售價 | **單一標準售價**（每 SKU 一價），開單預帶、單筆可覆寫；不做分級報價 |
| 分裝追溯 | **僅扣帳**：分裝記原裝 OUT＋分裝品 IN 兩筆異動，不建批號父子關聯（欄位預留可後啟用） |
| 規格 | **一個原裝品可分裝為多種規格 SKU**（一對多） |
| 效期 | **所有批號入庫／分裝時效期必填**，缺漏即拒絕；近效期查詢與 FEFO 依此運作 |
| 出庫策略 | **FEFO 先到期先出**，跨批扣減，僅取品管合格批號 |
| 倉儲 | 單倉，不做多倉／儲位 |
| 提醒 | 許可證到期提醒不做；低庫存與近效期查詢保留 |
| 資料庫 | **SQLite 單檔**（`data/animal_an.db`），SQLAlchemy 2.0 |
| UI 架構 | **本地 Web**：FastAPI 只聽 `127.0.0.1` ＋ 瀏覽器操控；PyQt5 棄用 |
| 打包 | PyInstaller 各打包 Windows .exe 與 Mac .app，啟動自動開瀏覽器；執行檔與 .db 分離 |
| 離線 | 完全離線：零雲端、零 CDN、零外連，備份＝複製 .db 檔 |

## 2. 業務背景

Animal-An 的營運模式：

- **進貨**：自原廠進口接近完成品的大包裝貨（棧板／桶／箱）——動物疫苗、衛生用品、營養補充品。
- **加工**：不做生產製造，只做**分貨／分包裝**，把大包裝拆成可售賣的小單位。
- **銷貨**：主要售予**養豬場**（疫苗接種、場區衛生、健康管理）。
- 同一原裝貨可分裝成**多種規格**，各規格有**各自售價**，且需反映在進銷存報表。
- 軟體於**不聯網的本地電腦**運作。

## 3. 系統架構

```
   採購(PO)            分裝(REPACK)                銷售(SO)
 ┌──────────┐        ┌──────────────────┐        ┌──────────┐
 │ 原裝品    │  OUT   │ X 原裝單位         │  IN    │ 分裝品    │
 │ BulkItem  │ ─────▶ │ = X × units_per_  │ ─────▶ │ Product   │
 │ (棧板/桶) │        │   bulk 售賣單位    │        │ (多規格)  │
 └────┬─────┘        └──────────────────┘        └────┬─────┘
      ▼                                                ▼
   ┌────────────────────────────────────────────────────┐
   │        InventoryTransaction（統一庫存帳本）          │
   │  item_kind=BULK/SELLABLE · IN/OUT/ADJUST            │
   │  ref: PO/REPACK/SO/ADJ · unit_cost · balance_after  │
   └────────────────────────────────────────────────────┘
```

技術分層（下層不得依賴上層 UI）：

| 層 | 位置 | 職責 |
|---|---|---|
| 前端 | `web/app.py` 內嵌 SPA | 瀏覽器頁面，零外部資源 |
| HTTP API | `web/app.py`（FastAPI） | REST 端點、序列化，只綁 127.0.0.1 |
| 業務邏輯 | `viewmodels/` | 進銷存交易、驗證、FEFO、成本 |
| 資料 | `models/` + SQLite | ORM 模型、統一帳本 |

## 5. 業務邏輯

### 5.1 進（原裝入庫）`receive_bulk`
- 必填：批號、數量、**批次成本**、**效期**——缺一拒絕，整筆不入庫。
- 同批號重複進貨累加數量；新批號預設品管狀態 PASSED。
- 寫帳：`IN / PO`，記 `unit_cost` 與 `balance_after`；主檔總量由批號自動彙總。

### 5.2 分裝 `repack`
- 驗證：SKU 必須屬於該原裝品、換算率已設定、原裝批號庫存足夠、產出效期必填。
- 產出量 = 耗用原裝量 × `units_per_bulk`；分裝品成本 = 原裝批次成本 ÷ `units_per_bulk`。
- 產生分裝單（自動流水號 `RPyyyymmdd-NNN`）＋兩筆帳：原裝 `OUT/REPACK`、分裝品 `IN/REPACK`。
- 僅扣帳：不建批號父子關聯；產出批號效期由操作者填入（通常抄原裝效期）。

### 5.3 銷（分裝品出庫）`issue_sales`
- **FEFO**：依效期升冪取量，僅取 `quantity > 0` 且品管合格批號，跨批扣減、每批一筆帳。
- 總可用量不足時**整單拒絕**（不部分出貨、零帳面異動）。
- 售價：預帶 SKU 標準售價，單筆可覆寫；明細記錄分配批號與該批成本（毛利計算依據）。
- 銷貨單建立時同步產生 SO 單頭與明細。

### 5.4 調整 `adjust_bulk`
- 盤盈（＋）／盤虧（−），不允許調成負庫存；寫 `ADJUST / ADJ` 帳並記原因。

### 5.5 帳本與一致性規則
- **所有庫存增減必經統一帳本**，每筆記 `unit_cost` 與 `balance_after`，可逐批對帳。
- 任一交易失敗即整體 rollback（不會出現「單頭建立但庫存沒動」的半套狀態）。
- 分裝前後庫存總金額不變（成本守恆）。

### 5.6 告警與查詢
- 低庫存：原裝品現量 ≤ 安全庫存。
- 近效期：原裝＋分裝批號合併、依效期排序（預設 90 天）。
- 庫存估值：Σ(批號量 × 批次成本)，原裝／分裝分列。
- 信用控管：客戶應收餘額超過信用額度時告警（M5 隨報表落地）。

## 6. 報表（M5）

報表以**規格（SKU）為列**，全部由本地 SQLite 產生：

| 報表 | 內容 |
|---|---|
| 進銷存月報 | 期初／本期進（含分裝產出）／本期銷／期末（數量＋金額） |
| 庫存即時表 | 各 SKU 現量、近效期批號、低於再訂購點標記 |
| 銷售毛利 | 依客戶／SKU 之銷量、售價、毛利（售價 − 批次分攤成本） |
| 分裝產出 | 原裝耗用 vs 分裝產出、換算差異 |
| 庫存金額 | 原裝與分裝分列 |

## 7. 離線與部署

- FastAPI 只綁 `127.0.0.1`；前端 HTML/CSS/JS 全部內嵌，禁止 CDN／外部字型／外部 JS。
- 依賴僅 FastAPI / uvicorn / SQLAlchemy；程式不得有任何對外連線、無遙測。
- PyInstaller 於 Windows 與 Mac **各自平台打包**（不可交叉編譯）；執行檔與 `.db` 分離，更新只換執行檔。
- 備份：`utils/backup.py` 每日／重大操作前備份至 `data/backups/`；還原＝複製 `.db`（USB 離線交付）。

## 8. 驗收條件

1. 原裝入庫必填效期與批次成本，缺漏拒絕；主檔總量正確彙總。
2. 分裝數量＝原裝×換算率、成本分攤正確、效期必填；分裝前後庫存總金額不變。
3. 一原裝品可建多規格 SKU 各自售價；開單預帶標準售價可覆寫。
4. 銷售依 FEFO 跨批扣減；不足整單拒絕且零帳面異動。
5. 每筆進／銷／分裝／調整在統一帳本留有 `unit_cost`＋`balance_after` 可對帳紀錄。
6. 供應商／客戶主檔可建立與編輯；應收超過信用額度告警。
7. 進銷存月報以 SKU 為列，期初／進／銷／期末（量＋金額）正確，離線可產生。
8. 全程無對外網路連線；business logic 層不依賴 UI，單元測試通過。
